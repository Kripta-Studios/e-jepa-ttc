## Compiler execution evidence

Each modality has three opaque dispatcher nodes in traced submodule graphs: A5 fine, C2F fine/coarse. Six compiled dispatcher invocations per active block occurred during initial evaluation, tracing, warmup and capture. No dispatcher callback occurred during timed CUDA Graph replays.

The parent inlined_graph view contains zero operator nodes in this PyTorch build; recursive submodule IR contains the nodes. Both views are preserved in *_jit_ir.txt. Initial gpu_idx0_v1 measured correct query-0 parity, but its final audit wrongly required the node in the parent inlined view. That failed result is preserved. Version 2 audits both views and preserves the full IR.

Executed source bytes are in gpu_sensitive_v2/sources/ with SHA bindings; later edits do not overwrite that evidence.

## Next controlled variants

--precision-mode no-fma adds emulate_precision_casts=True. --precision-mode no-fma-exact-div also adds eager_numerics.division_rounding=True. Both variants were subsequently measured and rejected; see PRECISION_VARIANTS.md.

Use --compiler-cache artifacts/train40_runtime_resume_20261027/compiled_pipeline/gpu_sensitive_v2 to reuse valid compiler keys. The driver records cache byte inventories before/after and excludes setup from warm latency. A precision option changes compiler keys; it does not guarantee the original ATen reduction order.

Do not promote a twenty-ROI run until all three TTC outputs pass the sensitive queries. The original graph runtime remains the admitted path.

The opacity and mutation contract follows the official [PyTorch custom operator guide](https://docs.pytorch.org/tutorials/advanced/python_custom_ops). This wrapper supports JIT-to-CUDA-Graph inference. It does not claim standalone graph serialization, outer Dynamo/export, autograd or vmap support.
